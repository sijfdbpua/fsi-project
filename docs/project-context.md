# Контекст проекта

Это источник сведений о конкретном проекте для обоих агентов. Дополняйте его
подтверждёнными решениями и проверенными командами через обычный PR. Этот файл
не является доской задач или механизмом блокировки.

## Текущее состояние

- Репозиторий: `sijfdbpua/fsi-project`.
- Основная ветка: `main`.
- До добавления совместного процесса репозиторий содержал только `README.md`.
- Код приложения, зависимости, тесты и CI пока отсутствуют.
- Стек, продуктовая цель и окружения приложения ещё не выбраны.
- 2026-11-10: список GitHub Rulesets пуст. Создание защиты `main` и чтение
  branch protection отклонены GitHub с HTTP 403 (`Resource not accessible by integration`).
  Техническое принуждение к PR и ревью не настроено; владельцу нужно включить его
  в GitHub Settings по [руководству](agent-workflow.md#первоначальная-настройка).
- Текущий процесс предполагает двух участников с отдельными GitHub-аккаунтами;
  их логины и распределение ролей фиксируются в задачах.

## Что определить перед первой реализацией

1. Для кого продукт и какую одну проблему он решает.
2. Минимальный пользовательский сценарий и наблюдаемый результат.
3. Что входит в первую версию и что пока исключено.
4. Стек и ограничения: платформа, версии runtime, хранение данных, интеграции,
   бюджет и требования к развёртыванию, если они известны.
5. Границы первого параллельного этапа: общий контракт, отдельные задачи,
   исполнитель и reviewer каждой, порядок интеграции.

Если ответы уже есть в запросе или документах, используйте их. Не спрашивайте
пользователя повторно. Необязательные детали можно заменить явно обозначенным
обратимым допущением; ключевые противоречия нужно разрешить до зависимых изменений.

Заполнить после появления выбранного стека; не выполнять эти строки как команды.

## Решения и контракты

Существенные решения записывайте здесь кратко: дата, решение, причина,
затронутые компоненты и ссылка на Issue/PR. Большие решения можно вынести
в отдельный документ и дать ссылку. Изменение API или схемы данных должно
содержать способ совместимости/миграции и затронутые задачи.

Непроверенные команды, отсутствие дефектов, доступность внешних сервисов,
настройки защиты веток и разрешение на деплой не следует предполагать.
