# fsi-project

Общий репозиторий для двух участников и их AI-агентов. Приложение, стек и команды
сборки пока не определены. Этот набор файлов организует совместную разработку;
он не запускает агентов и не синхронизирует чаты автоматически.

## Начать работу

1. Оба участника работают со своими GitHub-аккаунтами и отдельными рабочими копиями.
2. Перед каждой задачей обновите сведения об `origin/main` и прочитайте
   `AGENTS.md`, чтобы оба агента использовали актуальные общие правила.
3. Следуйте [первоначальной настройке](docs/agent-workflow.md#первоначальная-настройка)
   GitHub и возьмите стартовые промпты из того же руководства.
4. Создайте задачу через шаблон **Задача для агента**, назначьте исполнителя
   и второго участника на ревью. Один агент реализует, другой проверяет PR.
5. Для первого приложения сначала согласуйте цель, минимальный сценарий и стек
   в [контексте проекта](docs/project-context.md), затем добавляйте код и проверки.

## Где что хранится

| Файл | Назначение |
| --- | --- |
| [AGENTS.md](AGENTS.md) | Общие инструкции, которые должен читать каждый агент |
| [Руководство](docs/agent-workflow.md) | Роли, задачи, ветки, ревью, конфликты и готовые промпты |
| [Контекст проекта](docs/project-context.md) | Цель, архитектура и проверенные команды конкретного проекта |
| [Шаблон задачи](.github/ISSUE_TEMPLATE/agent-task.yml) | Цель, владелец, границы, зависимости и критерии готовности |
| [Шаблон PR](.github/pull_request_template.md) | Результат, проверка и передача на ревью |

Этот процесс можно перенести в другой репозиторий: скопировать `AGENTS.md`,
`docs/agent-workflow.md`, шаблоны `.github` и заполнить `docs/project-context.md`
по фактам нового проекта. Существующие инструкции сначала объединить с ними,
сохранив требования проекта. Статусы старых задач и секреты не переносить.
